# web-conversion

Cada sección de una web tiene un solo trabajo: acercar a la persona a la
acción principal. La que no lo hace no es neutra: distrae, cansa y hace que se vaya.

## Qué pedir

1. El link o el HTML.
2. La acción principal que quiere que haga la gente (escribir por WhatsApp,
   reservar, comprar, pedir presupuesto).
3. Si tiene datos, mejor: de dónde llegan las visitas y cuántos mensajes
   recibe. Sin datos, se trabaja con criterio y se aclara.

## Cómo revisar

Recorré la web de arriba abajo, como el cliente. Para cada sección, respondé:

| Pregunta | Si la respuesta es no |
|---|---|
| ¿Qué trabajo cumple? (informar, probar, resolver una objeción, invitar) | Es relleno: se saca |
| ¿Responde una duda real que frena la compra? | Se reescribe con la duda concreta |
| ¿Hay algo que hacer al terminar de leerla? | Se agrega el siguiente paso |
| ¿Tiene prueba real (foto propia, dato, reseña con nombre)? | Se marca qué prueba falta |
| ¿Se entiende en el celular sin hacer zoom? | Se simplifica |

Las objeciones típicas que una web tiene que responder antes de que pregunten:
cuánto sale, cuánto tarda, dónde está o a dónde llega, si es para mí, qué pasa
si no me sirve, quién está detrás.

## Qué entregar

1. **Mapa de la web:** cada sección en una línea con un semáforo
   (🟢 empuja, 🟡 a medias, 🔴 frena) y su trabajo. Acá el semáforo es
   información, no adorno.
2. **La sección que más frena**, con: qué dice hoy (cita), por qué frena, y
   la reescritura completa lista para pegar.
3. **Objeciones sin responder:** cuáles faltan y dónde ubicarlas.
4. **Orden sugerido** si cambiar el orden ayuda.
5. Si la acción principal está escondida o hay más de una compitiendo, decilo primero.

## Reglas

- No inventes testimonios ni cifras para "agregar prueba": marcá qué prueba
  falta y cómo conseguirla (pedir reseñas, sacar fotos de trabajos).
- No prometas un porcentaje de mejora.
